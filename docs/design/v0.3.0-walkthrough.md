# v0.3.0 walkthrough: design

Agreed on 2026-10-30, before tagging 0.3.0. Terms follow [GLOSSARY.md](../../GLOSSARY.md).

## Intent

A new user installs Proxy Toggler and has no guide inside VS Code: the README's Quick Start and
GIFs live on the Marketplace page and GitHub. 0.3.0 also adds two features that users who
already have it will not find on their own: proxies in integrated terminals and project defaults.
A walkthrough, VS Code's standard tutorial format on the Welcome page, teaches both in the editor,
and each step checks itself off when the user does it.

## Goals

- One walkthrough, **Get Started with Proxy Toggler**, of five steps. The first three set up and
  use a profile; the last two introduce 0.3.0's terminals and project defaults, so users who
  already have profiles can skip to them.
- Each step has one button that opens the place to act, and checks off when the user acts there.
- It ships in 0.3.0 and is listed in its CHANGELOG section.

## Non-goals

- No new extension code or command. VS Code opens a walkthrough when the extension installs, and
  **Welcome: Open Walkthrough…** reopens it.
- No recordings. The README's two GIFs (763 KB) would break the package's 256 KB budget in
  `scripts/check-package.cjs`, and the switcher GIF predates the **This Project** entries.
- No translations: `package.nls.json` is English only.

## Anti-goals

- A step never changes a setting itself: its button opens the switcher or the Settings editor, and
  the user decides.
- A step never suggests a project file that holds a proxy URL, or turning off certificate checks
  ([ADR 0006](../adr/0006-project-defaults-follow-the-focused-window.md)).

## Approaches

- **VS Code walkthrough** (picked): the standard format the user asked for, declared in
  `package.json` with no code, and its steps check off by command, setting or context key.
- **A tutorial section in the README**: lives outside the editor and cannot check anything off.
- **A custom webview tutorial**: extension code to write and test for what the walkthrough
  already does.

## Steps

| #   | Step                         | Button                                                         | Checks off on                                     | Markdown page                                         |
| --- | ---------------------------- | -------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------- |
| 1   | Add your proxy               | `proxyToggler.configure`                                       | `proxyToggler.hasConfiguration`: a profile exists | What a profile holds                                  |
| 2   | Turn it on and off           | `proxyToggler.toggle`                                          | toggle, Turn Proxy On or Off                      | The status bar states                                 |
| 3   | Switch profiles              | `proxyToggler.switchProfile`                                   | that command                                      | The switcher's entries, Test Connection, a keybinding |
| 4   | Use the proxy in terminals   | Settings editor on `proxyToggler.applyToTerminals`             | that setting changing                             | The variables, and what terminals never get           |
| 5   | Give a project its own proxy | `proxyToggler.switchProfile`, for its **This Project** entries | `proxyToggler.defaultProfile` changing            | The README's user and project settings example        |

## Decisions

- Titles and descriptions go in `package.nls.json`, as the commands' do.
- Every step's media is a Markdown page in `assets/walkthrough/`, which follows the color theme.
  `assets/**` is already packaged; `check-package.cjs` lists each page, and Prettier checks them.
- Step 1 checks off once any profile exists, so it does for a profile added from the switcher, or
  one a user already had.
- A unit test checks the manifest: every command a step's button or completion event names is
  contributed or built in, every setting is contributed, and every media file exists and is
  packaged. A typo would otherwise leave a step that never checks off, with no error.
- The work lands on `release/0.3.0`, in release PR #84.

## Left to the builder

- Step wording, kept to the README's terms and voice.
- Alt text for the GIFs, from the README's.
